# 学习路径与设计取舍

## 检索和生成分开理解

RAG 的检索部分应能独立运行并评测。本项目先返回可见的片段、位置和分数，再选择摘录回答或模型生成。这样可以定位问题究竟来自没有召回证据，还是模型没有利用证据。

默认摘录模式用于离线复现，不代表模型推理，也不是语义向量搜索。它让文档、引用和历史流程能够在没有付费依赖时被测试。

## 为什么按 Unicode 码点切分

Java String 的下标是 UTF-16 code unit。直接 substring 固定长度可能拆开 emoji 等代理对。分块按码点计算边界，保留 overlap，让跨边界短语仍有机会被完整检索。

## 中文 BM25 的取舍

英文可以按字母数字词切分；中文若只按空格分词，会把整段文字当作一个词。本项目使用汉字单字和相邻双字，易理解且无需外部分词模型，但可能召回只是字面相似的片段。

BM25 的分数不等于概率，也不能和其他模型分数直接比较。下一步应先建立问题、相关片段和无答案样本，再衡量 Top K 召回质量。

## 为什么保存引用快照

只保存文档 ID 会使历史在文档删除或修改后失去当时的证据。问答历史保存原片段快照，代表“当时用过什么资料”，而不是“当前库里仍有什么资料”。

## 真实模型的边界

模型收到的是问题和检索资料；资料不应作为系统操作指令。模型失败时显式返回错误，避免将摘录内容冒充模型输出。返回的检索引用只是证据输入，不能自动证明生成答案正确。

## 后续练习

建立小型评测集后，对比 BM25、向量检索和混合检索；加入去重、重排序与流式生成时，分别说明质量变化和失败处理。保留真实测试及复现记录。
