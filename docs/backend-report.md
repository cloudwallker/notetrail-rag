# NoteTrail RAG 后端实现报告

## 实现范围

后端使用 Spring Boot 3.5.11、Java 21、Spring JDBC 和 H2 独立实现。文档与块在一个事务中写入或删除；问答表保存回答、模式与引用快照，因此删除原文档后仍能查看历史证据。

检索器实现了 Unicode 码点安全的 500/80 分块、英文小写词元、中文单字与连续双字词元，以及 `k1=1.2`、`b=0.75` 的 BM25。排序仅保留正分结果，并提供确定性的同分顺序。

默认问答明确标记为 `EXTRACTIVE`。可选 `OPENAI_COMPATIBLE` 模式使用 JDK `HttpClient` 发起真实 HTTP 请求，发送问题和完整证据，禁止重定向，限制完整响应为 15 秒和 256 KiB。超时时会取消请求并关闭活动响应流。模型提示将证据标为不可信引用资料，要求忽略其中的操作指令。上游状态、正文与密钥不会透传给客户端。

API 对文本标量、`topK` 类型与范围、未知字段、重复字段、畸形 JSON 和顶层非对象值执行严格校验。错误统一为 `{code,message}`。

## 测试过程与结果

实现前先运行测试并观察到 9 个缺失生产类型造成的编译失败，随后分批实现代码。测试覆盖：

- Unicode 代理对、500 码点边界和 80 码点重叠。
- 中英文词元与 BM25 排序、无命中行为。
- 文档导入、列表、问答、历史快照、删除和 404 全链路。
- 空白与超长正文、严格 JSON 类型、非法 `topK`、重复及未知字段。
- OpenAI 兼容请求的鉴权头、模型、温度、问题与证据正文。
- 非 2xx、畸形或非文本回答、256 KiB 上限、总超时和安全 502。
- OpenAI 模式持久化及无证据时零模型调用。
- 独立临时文件数据库关闭并重新打开后的数据恢复。

最终执行 `mvn spotless:apply clean test`，结果为 17 个测试、0 失败、0 错误、0 跳过。测试日志确认 API 测试分别使用独立内存数据库，重启测试两次连接同一个 JUnit 临时目录文件数据库。受限文件沙箱内的 javac 曾在关闭 JDK `lib/ct.sym` 时触发 `AccessDeniedException`；在具备 JDK 路径访问权限的标准环境中，同一未跳过检查的 Maven 命令成功完成。

## 限制

- 检索是本地词法 BM25，不提供向量语义召回、OCR 或 PDF 解析。
- H2 适合单机学习和演示，不面向多节点并发部署。
- 引用表示发送给模型的证据快照，不构成对生成内容真实性的保证。
- 兼容模型仅支持 `/chat/completions` 返回 `choices[0].message.content` 文本的接口形状。
